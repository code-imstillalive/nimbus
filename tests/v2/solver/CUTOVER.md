# Solver area cutover ledger (#1837)

The design (#1837, 18 Oct): an old file is deleted only when the new layer
matches or beats the old on the area's mutation score and branch coverage,
**and** each old file's checks are covered by a named `tests/v2` test whose
docstring carries the old file's issue numbers, so `git grep '#NNN'` still
finds them.

Mutation scores (fixed runner `5acb2c20`, same mutants for both sets):

| module | old | new |
|---|---|---|
| `lp.py` (seed 7078, 20 mutants) | 13/20 | 18/20 |
| `network.py::_build_plan_once` (seed 1837, 30 mutants) | 22/30 | 24/30 (#1957) |

**In scope:** the old files whose only subject is `solver.lp` and
`solver.network` (they may build their inputs from `solver.elements`): 76
files. (69 at the first count; a strict import scan on 21 Oct found 7 more
that no row named, so the running "other N files" count below had been
too low.) Files that also test another module stay until that module's own
area is cut over.

**Out of scope, for `elements.py`'s own cutover** (the scores above do not
vouch for `elements.py`): `test_elements_battery_config_validation.py`,
`test_elements_adequacy_windows_validation.py`,
`test_elements_thermal_load_config_validation.py`.

**Out of scope, not solver tests at all** (they import neither `lp` nor
`network`; an earlier scan admitted them on text, not imports):
`test_settlement_capture_timing.py` (the standalone writer script's timing),
`test_docs_writer_function_set_drift.py` and
`test_1411_coverage_compare_matches_requalified_lines.py` (repo gates).

**How each row is checked:** read the old file in full; name the v2 test
that asserts the same thing (or write one); for a new guard, plant the bug
the old file was written for and show both sets fail.

## Found while checking

- **#1987, a real feasibility bug:** a battery above its Max SoC with terminal-value
  tiers, unable to get back under by the tier period, made the whole solve
  infeasible. #328 had folded underfill into the tier row for the floor side;
  the ceiling side was never done. Found by a v2 property; fix and property in
  #1988. The old file never tested the tier row below the floor either: its
  21 kW battery is back above the floor long before the tier period.
- **#1985:** a battery's ranged headroom could exceed its physical headroom,
  against its own docstring: HiGHS's bound ranging for a variable at its upper
  bound is not capped there (a battery charging flat out read 0.32 kW of room).
  Found by a v2 property over random sites; the old file's one scenario never
  hit it. Fix and property in #1986.
- **#481 with #897: past ~0.1/h a leakier tank plans less heat.** The coast
  reference front-loads the decay steps and the idle-fraction scaling cancels
  decay in the full-power periods where an early-heating plan sits, so total
  counted decay falls (24 h, ambient 0 C: 6.13 kWh at 0.10, 6.01 at 0.15, 5.75 at
  0.20). Monotone up to 0.1/h at every ambient scanned (0-30 C); a hot-water
  tank is nearer 0.01-0.03/h. Found by the v2 property on CI; it now draws
  0.005-0.09/h and says why.
- **#1981:** a shut period's `LoadSignals.degenerate` followed HiGHS's
  unclamped ranging, so a sheddable load in the same solve turned it off on
  a `[0, 0]` band (published for period 0). The old file's check held only
  with the adequacy load alone. Fix and test in #1982. Separately, neither
  the old file nor a floor-free v2 draw caught the sheddable band left
  unmirrored: [0, forecast] mirrors onto itself; a `min_fraction` floor shows it.
- **#478's adequacy anchor was untested.** `test_solver_adequacy_cross_solve_continuity.py`
  passes with the per-load anchor removed and with it matched by position:
  the grid import/export continuity reproduces the block on its own. The v2
  test zeroes the previous plan's grid flows to isolate it.
- **#1964:** the export-bonus tie-break (1e-7 per rank) loses to HiGHS's
  tolerance when the cap leaves a partial period, and the bonus scatters
  ON/OFF/ON. Found by the v2 property on CI, reproduced locally. Fixed by
  #1966 (secondary channel); the property now solves with production's options.
- **A real dispatch bug, fixed in #1963:** since 0.94.206 an adequacy load's
  `value_per_kwh` credit applied only to loads with `windows` (#634 put a
  windowed-only `continue` above it). Neither set caught it: the old
  profit-horizon tests only ever run a load its shortfall price already
  forces, and v2 had no value test at all until today.
- With export above import in every period of a 144-period, 5-minute plan
  (a synthetic arbitrage: 7.5c spread, no load), the direction-exclusive
  re-solve hit the 60 s per-call limit and the plan was kept two-way
  (`declined`, 84 pairs). The v2 spread property keeps plans to 12 periods;
  this is recorded here, not tested, until it is triaged on its own.
