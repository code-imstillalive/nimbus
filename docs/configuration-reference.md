# Configuration reference

Every field Nimbus's config-flow/subentry wizards and live dashboard entities
expose, in one place — for browsing before you install, or looking something
up after the fact without re-opening the wizard. The wizard itself has the
same explanations inline (`data_description` under each field); this page is
a scannable table version of the same information, generated by hand from
the real source so it stays accurate, not a copy that can silently drift.

If a field isn't listed here, it doesn't exist yet — every real field this
integration has, across every version, is covered below.

## Hub → Configure

Reached via Settings → Devices & Services → Nimbus → **Configure**. Three
steps, only the first two are mandatory for a functioning install.

### Forecaster settings

Shared by every Load and Power Signal you add — set once here rather than
re-entering per load. All optional; the Forecaster works with zero of these
filled in.

| Field | Purpose |
|---|---|
| Temperature sensor | Real outdoor/ambient temperature — a model input feature (e.g. "AC load rises with temperature"). |
| Temperature forecast sensor | A sensor exposing a forward-looking temperature forecast attribute, so predictions for *future* periods use tomorrow's forecast, not just today's reading. |
| Humidity sensor | Real outdoor/ambient humidity — same role as temperature, for humidity-correlated loads. |
| Curtailment switch | A switch/binary_sensor that's ON when your inverter is actively curtailing solar. Only relevant for a load run specifically to soak up otherwise-wasted solar (e.g. a pool heater). |
| Battery power sensor | A real, measured battery power sensor (shared "Power Signal" role) — never an optimizer's own plan/forecast entity. |
| Grid power sensor | Real, measured grid import/export power — same caution as above. |
| Solar power sensor | Real, measured solar production power — same caution as above. |
| Forecast horizon (hours) | How far ahead each load's forecast array extends. |
| Retrain hour (local, 0-23) | The local hour Nimbus retrains every model from scratch against Recorder history. Pick a quiet hour. |
| Training window (days) | How many days of Recorder history each retrain looks back over. |

### Solver settings (3-step sub-wizard)

**Mandatory if you want the Solver at all** — see the top-level README's
"Running the Solver" section. Deliberately just sensor pointers; every plain
numeric setting lives on its own live `number.nimbus_solver_*` entity
instead (table below) so you can tune it without re-running this wizard.

**Step 1 — Battery:**

| Field | Purpose |
|---|---|
| Battery State of Charge sensor (%) | The live sensor your system already reports (e.g. from your inverter's own integration). Read at the start of every solve — must be a genuine 0-100% measurement, not a target/setpoint entity. |

**Step 2 — Grid Prices:**

| Field | Purpose |
|---|---|
| Live import (buy) price sensor ($/kWh) | From your retailer/market integration. If it has its own forecast attribute, the Solver uses it directly; otherwise the current value is held flat across the horizon. |
| Live export (sell) price sensor ($/kWh) | Same, for what you're paid to export. |

**Step 3 — Solar & Load Forecasts:**

| Field | Purpose |
|---|---|
| Solar generation forecast sensor | Solcast, Open-Meteo Solar Forecast, or a Nimbus Power Signal on your own inverter's DC power. |
| Household load forecast sensor | The single sensor treated as "total household load" — e.g. a Nimbus Power Signal on your whole-house meter. |
| Individual circuit forecast sensors (optional) | Sum several per-circuit forecasts instead of one whole-house sensor — leave blank to use the field above. |
| Whole-house cross-check sensor (optional) | A real, currently-measured (not forecast) whole-house sensor the Solver compares its own first forecast period against, as a live sanity check. Has no effect on the actual dispatch plan. |

### Topology diagram: Switchboard

Grid power, battery power, and every Load are auto-detected — nothing to
configure for those. Every field below is optional and purely for the
topology dashboard card.

| Field | Purpose |
|---|---|
| Current buy/sell price sensors | **Fallback only** — if any Solver settings are configured, the card reads price from there instead. |
| Import/export/house-load/solar energy today (kWh) | Daily-resetting `utility_meter`-style sensors, shown as headline stats. Nimbus has no equivalent of its own (it forecasts power, not accumulated energy). |
| Battery charged/discharged today (kWh) | Same, for the battery's own daily totals. |

## Adding a Load

Reached via **+ Add** on the hub's device page. One required field, three
optional and genuinely per-load (unlike everything above, which is shared).

| Field | Purpose |
|---|---|
| Power sensor to learn from | A real, measured power sensor for one circuit/appliance (kW or W) — e.g. a smart breaker on your HWS, pool pump, or EV charger. |
| Fixed schedule start/end hour (optional, 24hr decimal) | For a load with a real fixed daily timer (e.g. a pool pump running 8am-3pm), lets the model learn the sharp on/off boundary directly. 24-hour decimal (12.5 = 12:30pm) to avoid AM/PM ambiguity. Leave both blank for a load with no fixed schedule. |
| Expected power while running (optional, kW) | Only meaningful alongside the schedule window — a sensible starting point for what "on" looks like, refined from real history as it retrains. |

## Adding a Power Signal

Forecast a real signal (Battery, Solar, Grid, or anything else) directly, as
its own target — same engine as a Load, different intent.

| Field | Purpose |
|---|---|
| Power sensor to forecast | A real, measured whole-system sensor — e.g. total battery power, total DC/solar power, or total grid meter power. Never an optimizer's own plan/forecast entity. |
| Role (optional) | Battery / Solar / Grid / Other — purely a labelling hint for the topology dashboard card's auto-detection, no effect on forecasting itself. |

## Topology-only subentries

These three exist purely as wiring metadata for the topology dashboard
card — none of them are forecast targets.

**Power Source** — one real hardware unit (inverter, hybrid battery/inverter,
or battery-only unit):

| Field | Purpose |
|---|---|
| Name | Free text, shown on the diagram (e.g. "Inverter 1"). |
| Battery power sensor (optional) | This specific inverter's own signed battery power. Leave blank for a PV-only source. |
| Total DC power sensor (optional) | This inverter's own total DC power — genuinely different from battery power, since it reflects real solar throughput regardless of what the battery is doing. |

**PV String** — one real physical PV string/array:

| Field | Purpose |
|---|---|
| Power sensor for this string | Real per-string power — e.g. an MPPT/string-level register, not the inverter's total DC power. |
| Label (optional) | Free text, e.g. compass direction or roof section. |
| Power Source (optional) | Which inverter this string is wired through, if any. |

**Battery Tower** — one real physical battery pack/tower. Every field
optional; fill in whichever your hardware exposes:

| Field | Purpose |
|---|---|
| State of Charge sensor (%) | This tower's own SoC, if exposed per-tower rather than only combined. |
| State of Health sensor (%, optional) | This tower's own SoH — remaining capacity relative to new, not related to SoC. |
| Voltage / Temperature sensors (optional) | This tower's own real-time readings, if exposed per-tower. |
| Power Source (optional) | Which inverter this tower belongs to, if your system has more than one. |

**Notes:**

- Fields whose default is their own **minimum bound** (Battery Capacity,
  Max Charge/Discharge Power, Grid Max Import/Export) have no real universal
  default — they're genuinely household-specific hardware numbers. On a
  fresh install, these sit at that placeholder minimum until you set your
  real values (a persistent notification points you here the moment the
  hub is created).
- **P2P Block 1-3** (rate + start/end hour): up to 3 independent fixed-rate
  export windows, each holding export at a constant user-set rate rather
  than letting the Solver chase price within it — `rate_kw = 0` means "not
  configured." End hour allows `24` (not just `23`) so a window can reach
  midnight (e.g. a 17-24 window means 5pm through end of day).
- **Network Fee** fields accept 6 decimal places (`step = 0.000001`), not 4
  — real retailer tariffs (e.g. a time-of-use network tariff) can need that
  precision to enter exactly without silent rounding.
- **Risk Aversion / Import Price Risk Aversion / Export Price Risk
  Aversion** are unitless (0 = ignore forecast uncertainty entirely, 1 =
  fully hedge toward the pessimistic confidence bound). Import and export
  are independent dials — hedging against import-price risk should not
  automatically also hedge export-price risk, since they're economically
  opposite decisions.
