**Implemented #678: `_offer_curve_ranging_walk()` replaces `_offer_curve_price_
grid()` entirely.** Starts at the real AEMO Market Floor Price (−$1.00/kWh,
confirmed genuine by #675, not synthetic), and repeatedly calls `sweep_cost_
with_ranging()`, using each step's own exact `cost_up` boundary (nudged forward
by a small relative epsilon, same magnitude as `lp.py`'s own #696-ported
`LexOptions` phase-3 epsilon) as the next price to solve at — walking every real
segment between the floor and the Market Price Cap exactly, capped at 8
breakpoints (real data shows 2-4 per side), rather than hoping a fixed sample
lands near a real breakpoint. Retail is always separately swept regardless,
preserving #494's own "curve at retail equals the main plan's dispatch"
guarantee. This directly answers #678's own two explicitly-flagged open
questions: the boundary epsilon nudge is genuinely necessary (confirmed live —
the boundary price itself is a real LP tie between two adjacent plateaus, not
solved reliably by landing exactly on it), and the safety cap is a hard
iteration bound plus an explicit non-monotonic-ranging stop, not left unbounded.
Real, concrete proof the walk finds more than the old grid ever could: run
against this project's own existing `_scenario_plan()` test fixture, it found a
genuine 2.0 kW import plateau and a genuine 0.1 kW export plateau — both real,
both between −10¢ and 10¢ — that #494's original fixed 7-point grid never
sampled finely enough to see, in a fixture this test suite has used since #494
first shipped. Supersedes #675's own "add forecast min/max as extra points" ask
per that issue's own text (a walk needs no landmarks once it finds every real
breakpoint exactly); #675's separate "is $20 stale" sub-question is untouched,
left for whoever picks that up with real primary-source access.
