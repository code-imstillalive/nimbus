## The test box rebuilt

The household's plan of 22 Oct: replace the test box's mirror of production
with a read-only MQTT feed of production's source readings, and reinstall
Nimbus clean against it.

- **Feed.** Production publishes its source sensors read-only; the test box
  receives them and keeps prefixed, read-only copies. A small test-box-only
  integration keeps each source's full state and every attribute (an MQTT
  discovery sensor can read only one attribute topic, and an automation that
  merged them could not keep up with the message rate). 91 of 95 copies match
  production value-for-value and attribute-for-attribute; the other four are
  live values that moved between reads, one text-with-unit state Home
  Assistant refuses, and a display mode.
- **Mirror removed** (household, in the UI), with the ~3,200 registry orphans it
  left. The test box can no longer call production's services.
- **Nimbus reinstalled.** The first rebuild copied the test box's own stale
  settings instead of production's: wrong price sensors, no schedules, wrong
  training window, 11 sources missing from the feed. Rebuilt again from
  production's diagnostics, field by field; the remaining differences are the
  horizon (the form's minimum is now 97 h, production stores 96), the training
  source (hybrid, below) and the test devices, which the household keeps.
- **History.** A clean install has none, and a model needs 500 points (about
  five days). Production's 45 days of hourly long-term statistics were imported
  for the training sensors and training set to `hybrid`; every model trained
  and the Solver planned `optimal`.

## Found by the clean install, fixed in #2021 (open, checked on the test box)

1. **Topology: the EV was missing.** Battery participants were drawn only on
   an install with no Topology subentries at all.
2. **Topology: no daily solar / battery / load figures.** They drew only with a
   `whole_house` block in the card YAML, which the generated dashboard never
   writes; the headline now comes from the Solver config.
3. **Solver tab: one SoC for house and EV together.** "Battery, now" and "At a
   glance" showed the fleet figure; each battery now gets its own row and ring.
4. **Topology: an empty Grid box.** With signals left at role "other" there was
   no grid meter (the Switchboard wizard no longer asks for one); the card now
   falls back to the Forecaster's own Grid and Battery sensors.
5. **Topology: controllable loads missing** (heat pump, pool pump, HWS,
   appliances). They publish no forecast, the only thing the card listed loads
   by; the topology sensor now lists them with their own entities.

Each new test fails on `main` and passes with the fix.

## Findings

- **Stochastic solve size.** With an EV and six controllable loads the joint
  stochastic problem has 37,608 variables and 432 paired stage-1 decisions,
  against 17,484 and 96 on a battery-only site; it took 97.7 s against 7.0 s,
  and some runs hit the time limit and fall back. An install with an EV and a
  few controllable appliances sits near that edge. Issue to be drafted for the
  household's approval.
- **Card caching.** The card scripts are cached by version, so a patched,
  unreleased card needs a hard reload in the browser.
- A save taken before deleting a config entry must read the stored values, not
  each field's default: the one taken today missed every suggested-value field.
