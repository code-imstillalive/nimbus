## #1705: the four "frozen" Solver sensors are not frozen

Mark reported `lp_status`, `current_dispatch_direction`, `n_clamped_periods`
and `binding_constraint_now` stuck at their first value after a restart.
Production at 18:14 told two different stories depending on how they were read:

- `/api/states` `last_reported` read 15:45, 15:45, 16:59 and 17:45.
- `states.X.last_reported` read through `/api/template` was 18:10:53 for all
  four, the same second as `solve_seconds`.

HA core does not build a new `State` when a write is unchanged. It moves
`last_reported` on the existing one and fires `state_reported`. But
`as_dict` / `as_dict_json` are cached and not invalidated, so REST, the
websocket and ha-mcp all keep serving the old timestamp, and no history row is
written. Sensors whose value holds still therefore look frozen. Posted to
#1705, with the template check for Mark to run on his install. Not assumed to
match his.
