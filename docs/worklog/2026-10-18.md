## DC-004 (#1838)

The spec answers the roadmap's two DC-004 risks: two masters, and storage that a code revert does not revert.

- **Three modes per config entry.**
  - `legacy`: every install today.
  - `shadow`: the document is stored and compared, and the legacy settings stay master.
  - `active`: the document is master, and today's settings are one-way generated views.
  - Each step is a household action, and `active` → `legacy` is always available.
- **Two masters already exist today.** Battery capacity and the grid limits live in the options and again in live number entities, which the solve reads. Import names this as `conflict_setting_copies` rather than picking one.
- **Rollback boundary.** Views use only keys the previous release understands, so a code downgrade runs on the last committed configuration.
- **Control authority** is imported unchanged: `authorised` only where a Controllable Load already has a device entity.

The decisions for Mark are tabled in the spec. Posted on #1574.
